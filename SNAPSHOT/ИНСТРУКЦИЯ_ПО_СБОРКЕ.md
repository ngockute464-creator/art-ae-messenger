# Инструкция по сборке АРТ-АЕ — ТЕКУЩАЯ схема Netlify

**Это восстановление существующего способа сборки, а не новая сборка для VPS.**

Ревизия: `6def41af7809c746b9d52820e0a543c3a0490e6e`, ветка `netlify-preview`.

## 1. Что необходимо

- Git и доступ к GitHub (включая чтение upstream VibeOffice).
- Node.js **24.x** (ориентир на текущие скрипты и проектную среду).
- Утилита `unzip` для Unix/Linux; на Windows — PowerShell Expand-Archive.
- Netlify Site со сборкой из указанного репозитория и ветки.
- Подключённые Supabase PostgreSQL / Realtime, Яндекс Диск; Cloudflare для расшифровки.
- Переменные окружения из `SNAPSHOT/ПЕРЕМЕННЫЕ_ОКРУЖЕНИЯ.example` со своими действительными значениями.

## 2. Официальный существующий build в Netlify

В корневом `netlify.toml` дословно указан command:

```sh
unzip -oq artae.zip -d . && node build/prepare.mjs
```

Публикация:
```toml
[build]
  command = "unzip -oq artae.zip -d . && node build/prepare.mjs"
  publish = "public"
  functions = "netlify/functions"
```

**Порядок принципиален.** `artae.zip` содержит исходную базовую версию `public/` и Netlify Functions. `build/prepare.mjs` поверх неё:

1. Копирует серверные модули из `server/` в `netlify/functions/`;
2. Включает собственную PostgreSQL-авторизацию `server/auth-pg.mjs`;
3. Применяет строковые патчи клиента, Realtime, проводника, вложений, голосовых и UX;
4. Обновляет service worker и метаданные версии;
5. Запускает `server/office-patch.mjs` либо изолированный `office-site/integration/office-patch.mjs` при заданном `ARTAE_OFFICE_ORIGIN`;
6. Проверяет синтаксис конечного `public/app.js` и обязательные функции интерфейса.

**Не заменять** вложенный `artae.zip` исходниками из других версий; патчи ожидают конкретную структуру базового приложения.

## 3. Локальная подготовка без деплоя

Сделайте рабочую копию архива в отдельную папку. **Распаковка в существующую рабочую директорию с изменениями может их перезаписать.**

Linux/macOS:
```sh
unzip -oq artae.zip -d .
node build/prepare.mjs
node --test tests/*.test.mjs
```

Windows PowerShell:
```powershell
Expand-Archive -LiteralPath .\artae.zip -DestinationPath . -Force
node .\build\prepare.mjs
node --test .\tests\*.test.mjs
```

Для полноценной проверки HTTP-маршрутов нужен совместимый runtime Netlify Functions, например Netlify CLI (`netlify dev`) и **реальные переменные окружения**. Один лишь `node build/prepare.mjs` не запускает серверные функции.

Если внешний GitHub недоступен или pinned upstream VibeOffice отсутствует, сборка редактора должна **остановиться с ошибкой**; не заменять редактор «похожим» без тестирования.

## 4. Проверка артефакта сборки

После успешного запуска должны существовать:
- `public/index.html`, `public/app.js`, `public/styles.css`;
- `public/sw.js`, `public/manifest.webmanifest`, `public/app-version.json`;
- `public/office/quire/`, `public/office/ledger/` при сборке same-origin Office;
- `netlify/functions/auth.mjs`, `sync.mjs`, `files-explorer.mjs`, `voice.mjs`, `voice-transcript.mjs`, `pins.mjs`, `realtime-token.mjs`.

Unit/static tests **не заменяют** браузерные интеграционные проверки. Проверить вход, проекты, чаты, вложения, голосовые, редактирование и сохранение DOCX/XLSX, блокировки, realtime, PWA.

## 5. Раздельная сборка Office (НЕ стандартная)

Файлы `office-site/` описывают эксперимент изоляции VibeOffice на отдельном домене:

```sh
node office-site/build.mjs
```

Требует заданного точного HTTPS origin `ARTAE_PARENT_ORIGIN`, а созданные файлы публикуются из `office-site/dist`. Отдельный домен должен пройти CSP, CORS и postMessage проверки **до** включения `ARTAE_OFFICE_ORIGIN` в основной сборке. По умолчанию работает штатная same-origin ветка.

## 6. Принципы безопасного восстановления

- До запуска восстановить секреты **из менеджера секретов/настроек Netlify**, не из ZIP (их здесь нет).
- При подключении к действующей Supabase **не применять заново** `sql/core-schema.sql` и другие миграции без отдельной проверки состояния; SQL в архиве предназначен для изучения/развёртывания.
- Не включать свежий bootstrap новых администраторов на действующей базе.
- Старые PWA cookie привязаны к домену. При смене домена пользователи входят повторно.
- `netlify-preview` сейчас блокируется квотой Netlify; наличие кода не восстанавливает доступ без другой рабочей среды.
- Ничего не переключать в DNS и не удалять GitHub/Netlify/Supabase/Яндекс Диск до реального end-to-end теста.

## 7. Чего этот архив не включает

Нет значений секретных ключей, дампа рабочей базы, содержимого Яндекс Диска, текущего состояния Netlify, внешнего upstream VibeOffice и готового полного для VPS runtime. В архиве присутствуют исходники, сборочная основа, конфигурация, SQL и тесты — достаточно для воспроизведения **процесса сборки**, если внешние зависимости доступны.
